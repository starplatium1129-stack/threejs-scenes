## 完整提示词

请直接使用 Three.js 制作并验证一个完整、可运行的「博丽神社 · 幻想乡庭院」微缩三维场景。请一次性完成以下所有要求，不要先交付基础版，也不要等待我逐轮要求补充建筑、像素角色、写实材质与茂密植被。

### 1. 交付与交互

- 使用独立的 `hakurei-shrine/` 子目录组织项目，采用 Three.js、Vite 和模块化 JavaScript，提供 `npm install`、`npm run dev`、`npm run build` 的运行方式。
- 画面以三维场景为主体。唯一 UI 是左上角精简的时段控件：小字「博丽神社 · 昼 / 暮 / 夜」，下方胶囊按钮「昼夜流转 / 白昼 / 夜晚」。默认白昼，当前选项清晰高亮，支持键盘操作；移动端保持紧凑，不遮挡模型。不要加入其他导航、操作面板、加载覆盖层或托管水印。
- 第三人称观察一个完整的可收藏微缩模型。支持鼠标拖动旋转、滚轮缩放和触摸双指缩放；旋转有阻尼，可从各方向检查建筑，限制相机钻入地底。
- 初始机位位于神社正面偏右上方，完整呈现正方形底座、建筑和树冠。构图紧凑但四周留白，手机竖屏也不能裁掉底座。
- 背景为低饱和渐变天空与几层淡化的远山剪影，白昼使用青绿至暖灰的空气透视，夜晚使用深蓝天空、细星点与柔和月亮；背景随昼夜连续变化，不能抢过微缩模型。底座下保留轻柔落影，不要街景、城市背景或额外漂浮小岛。

### 2. 美术方向：半写实三渲二

- 保留浓厚的日式二次元、幻想乡与宁静神社氛围，同时让建筑和地物具有可信的比例、连接方式和材料表现。
- 参考《明日方舟：终末地》环境美术中「克制配色、真实结构、细致材质、动漫式明暗层次」的方向，但场景主题仍然是博丽神社；不要加入科幻工业设施。
- 不要积木式建筑、塑料质感、糖果色、球团树冠或低多边形圆块灌木；也不要完全转成摄影写实，或用一张静态插画冒充可旋转模型。
- 环境采用 PBR 表面响应与柔和分段漫反射相结合的三渲二材质：木材、石材、瓦片、金属分别具有合适的粗糙度、细微凹凸和反光，漫反射保留约 3–4 档主明暗关系，阴影略偏冷。
- 色彩以旧朱红、暖灰木材、灰白纸墙、深灰青瓦、低饱和草绿和淡粉樱花为主。光照是带冷色环境补光的柔和暖日光，避免过曝、浓黄滤镜和纯黑死阴影。
- 增加一棵位于后右方的黄绿色树冠，搭配粉色樱花和深绿色树木，组织出清楚的暖冷色块。借鉴精致神社微缩景观的建筑剪影、景观分组和留白，而非仅堆叠细节；细枝叶片与半写实材质继续保留。
- 纹理要有近看细节，但不能粗糙到像脏污噪点，木纹不能变成规则波纹，石纹不能像夸张大理石花纹。

### 3. 底座与空间布局

- 全部元素都搭建在一个约 15×15 单位的完整正方形底座上。
- 底座有清楚的分块石砌侧面、薄木制夹层、上沿压边和轻微圆角。边缘规整，接缝、材质与层次可从斜侧面清楚辨认。
- 神社本殿位于后方偏中央，约占底座宽度一半。后部抬高为石砌平台，前部是开阔庭院，形成前低后高的空间层次。
- 石板参道沿前后方向通向本殿，中间有石阶衔接。前方鸟居构成入口框景，不能把灵梦和本殿长期完全遮住。
- 庭院右侧有窄石板小路、后右侧有独立社务所或小仓库、左侧有手水舍和告示牌，周边有木围栏。

### 4. 建筑：可以从所有方向近看

- 本殿具备红白木构、深灰青曲面瓦顶、宽屋檐、门扉、纸拉门、侧窗格栅、木侧墙、木地板、台阶、回廊和栏杆，不能只是正面贴图或空壳。
- 主屋顶高挑，坡面具有明显的内凹曲线与适度上翘的檐口；不要宽平的一整片屋面。具备逐片搭接的浅弧形瓦片、瓦缝、瓦当、檐口厚度、压脊和山墙收边，近景可读出搭接关系。山墙和支撑必须处于瓦面之下，不能穿出屋顶。
- 正门前设置独立的投影门廊与小山墙屋顶，具有双柱、托木、斜撑、横梁和少量金色装饰。小屋顶的屋脊与主屋顶形成方向和高低变化，连接完整，突出参拜入口、赛钱箱和台阶的仪式感，不遮住角色主要活动区域。
- 檐下有椽条、椽头端面、横梁、托木和支撑构件；回廊下有支柱与斜撑；木构连接处有克制的金属柱脚、销钉和五金件。
- 门窗格栅具有厚度与阴影，木地板逐条铺设，踏步有收边、钉头与轻微使用痕迹。
- 正面有带顶部栅条的赛钱箱，悬挂神社铃与红白铃绳，横向注连绳上带纸垂；牌匾写「博麗神社」，赛钱箱可写「奉納」。
- 屋檐下有小型暖色祭典灯笼；侧后部有雨链、接水石和基础旁的排水槽。
- 鸟居使用克制的朱红与深色顶部横梁，柱脚稳定落在基石上，有额束、牌匾、注连绳与纸垂。

### 5. 庭院地物与使用痕迹

- 参道使用逐块石板，有细小缝隙、轻微磨损、少量细裂纹和边缘变化，不要完全均匀的平面网格贴图。
- 石阶、石灯笼、平台挡土石和散石都要体现石材厚度、矿物颗粒与轮廓变化；较大的岩石具有不规则轮廓和轻微层理。
- 庭院应包含：石灯笼、手水舍与石水盆、竹杓、小告示牌、绘马架、御神签架、备用扫帚、木桶、储物箱、带端面年轮的柴堆、围栏与边缘小路。
- 手水舍的水面有轻微涟漪。绘马有小木牌与挂绳，御神签有折叠或系结的白纸。
- 树根、石缝和阴处有苔痕；参道两侧有细碎石，地面散落少量枝条、落叶和花瓣。整体有维护与生活痕迹，保持整洁宁静。

### 6. 茂密、有层次的植被——必须在首版完成

- 不要只摆几棵树和零星几根草。最终画面中，左右庭院边缘、树下和围栏旁应有明显成片的茂密草地，覆盖足够面积，形成自然的庭院绿化。
- 草地具有疏密变化、几种低饱和绿色、深色根部与较亮草尖，以及约 0.08–0.30 单位的高低差。可参考约 8,000–9,000 个草簇、约 26,000 根草叶的细节量，并采用实例化保证性能。
- 草丛下有低矮绿色地被，局部穿插约十余丛蕨类、低矮灌木和少量乳白/淡紫野花；花只作为点缀，不要变成花海。
- 蕨类具备从中心向外伸展的弯曲羽状叶片，灌木由枝条与叶片组成，树木有弯曲树干、根系、分叉枝条和自然树冠。
- 布置两棵淡粉樱花与若干绿色树木。樱花树冠由细小五瓣花簇组成，绿树由独立叶片组成；绝不能用巨大的圆球堆出树冠。
- 草地主要集中在庭院边缘和阴处，并向开阔区自然变稀；参道、净手区、告示牌前、绘马架前、台阶及灵梦完整扫地/跳跃路线必须留出空地。
- 将左右前院、后方树下等绿化组织成数块清晰的景观区域，每组结合乔木、灌木、蕨类、岩石和草地；以自然弧线和疏密变化连接，保留呼吸感。避免所有边缘均匀铺满，或远看只有细碎噪点。
- 所有植物和根系都在方形底座内，不能长穿屋子、台阶或石板，也不能越出底座漂浮。

### 7. 灵梦：先图像生成，再据图整理像素角色

- 在前院放置清晰可辨的 Q 版博丽灵梦。若已附带 `reimu-reference-v1.png`，直接复用该底稿以保持一致；若没有素材，必须先使用图像生成功能制作一张高质量、透明背景、完整全身的像素风灵梦立绘，然后以它为底稿整理图集，不要再次只凭简单矩形和多边形拼一个模糊小人。
- 人物有深棕长发、分层刘海、红色眼睛、巨大红蝴蝶结及白色褶边、红白巫女服、裸露肩部与独立宽袖套、白边红裙、白袜和红鞋，手持传统长柄竹木扫帚。
- 约 2.5 头身，五官、长发、衣袖与扫帚都要分得开。轮廓使用深棕色而非刺眼纯黑，颜色鲜明但不过分饱和。
- 以人物底稿为身份参考，另外生成 4 列 × 3 行的真实姿态动作底稿，或直接复用 `public/assets/reimu/reimu-motion-v2.png`。整理为约 272×208 像素单帧、12 帧透明图集，横向留足扫帚空间，统一比例与鞋底落点。采用最近邻采样；清理背景时必须保留白袖、褶边和发丝，不得出现袖子破洞或扫帚截断。
- 角色在世界中约 2 单位高，保持适当可读性而不压过建筑。使用受光的二维面片，随相机水平转向，仍有场景光照与按透明轮廓形成的柔和阴影。

### 8. 灵梦完整动作循环

- 使用约 6–8 帧/秒的非均匀节奏，以准备、伸出、落帚、拉扫、收势、抬帚、回收、复位组成真实扫地循环。每帧双手位置、扫帚角度、肩部重心、袖子和裙摆确实不同，不能只扭曲整张立绘伪装动作；握持关系连贯，不出现断臂、破洞或裁切。
- 每处扫约四轮，停顿，然后轻轻跳到前院的下一处空地；不能一直固定在一个位置。
- 循环包含扫地、停顿、起跳预备、腾空、落地缓冲几个阶段。可采用约 8.8 秒一轮、约 5.4 秒完成四轮扫地、约 0.81 秒跳跃，跳高约 0.48 单位。起跳使用独立屈膝姿态，空中收腿并带裙摆惯性，落地依次缓冲、起身、站稳。
- 跳跃在多个安全落点间循环。站立和落地时脚底必须贴合地面或石板实际高度，不能穿地、悬空或滑动。
- 跳跃时地面影子不随角色升空，而是跟随其水平位置；高度越高，影子越大、越淡。
- 扫帚头按实际扫动范围接触花瓣，仅在贴地拉扫阶段推动，抬帚、回收和跳跃时不能推动。停顿阶段先收帚，再用约半秒短转身切换方向，左右交替，不能突然镜像闪切。
- 站立也有极轻微的呼吸和重心变化，动作保持精致小景观的安静感。

### 9. 环境动态与性能

- 昼夜是完整的光照与背景系统，不是简单调暗屏幕。白昼有暖日光与冷环境补光；夜间用冷月光保留瓦顶、树叶和底座的结构，纸窗透出暖光，檐灯、门廊、社务所、手水舍与石灯笼点亮并照亮邻近木地板、石阶或参道，形成明确的冷暖对比。
- 「白昼」和「夜晚」平滑过渡，不突变；「昼夜流转」可在约 180 秒内自动往返日夜，标题随实际光照显示昼、暮、夜。三个按钮反映当前模式，不能影响相机拖拽和角色循环动作。夜景避免大范围死黑或窗户过曝成纯白方块。

- 草尖轻摇、树叶与花簇轻晃、绘马和纸垂微摆、铃绳微摆、灯笼光轻微起伏，少量花瓣缓慢飘落，可有非常克制的微光粒子。
- 不要大幅风摆、自动不停旋转相机、强烈泛光、密集粒子或抢眼的灵气特效。
- 建筑静态几何按材质合并，草叶、花簇、蕨类等重复地物采用实例化；动画对象保留独立控制。草地风动可使用轻量顶点着色器。
- 限制像素比，合理配置阴影和相机范围，桌面与移动端都能交互。运行时不依赖外部图片或模型服务。
